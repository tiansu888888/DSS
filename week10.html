Step-by-Step Guide 分步指南

7.1 Planning for DSS & Feasibility Study

  • Scope Definition: Establishing boundaries, business objectives, user counts, and identifying key decisions to support.
  • Feasibility Study Dimensions:
    • Economic Feasibility: Cost-benefit analysis comparing development cost against predicted operational profit and time savings (ROI).
    • Technical Feasibility: Assessing if current hardware, server capacity, database tools, and software interfaces can support requirements.
    • Organizational Feasibility: Evaluating user willingness, training needs, and business politics to ensure system adoption.

Real-world Case: Healthcare.gov Launch (2013)

  • The initial Healthcare.gov portal suffered severe technical and organizational planning oversights.
  • Poor requirements gathering and lack of scalability testing led to a total server crash upon public release.
  • This highlights the critical importance of a rigorous technical feasibility audit before deployment.

Reference: The Healthcare.gov Failure: A Retrospective

Feasibility Analysis Criteria

Feasibility Dimension Core Question Typical Metric Key Risk Vector
Economic Should we build it? Net Present Value (NPV), ROI, payback period Underestimating server and API operational costs
Technical Can we build it? Skills matrix check, hardware availability Using experimental library setups with no support
Organizational Will they use it? User satisfaction survey, process alignment Resistance from managers who prefer intuition over data

Defining exactly what is included in the project boundaries, preventing scope creep during development.

7.1 DSS 系统规划与可行性研究

  • 范围定义 (Scope Definition)： 确定系统边界、业务目标、用户数量，并确定要支持的关键决策。
  • 三大可行性分析维度：
    • 经济可行性 (Economic)： 进行成本效益分析，对比开发成本与预测的运营利润及时间节省（投资回报率分析）。
    • 技术可行性 (Technical)： 评估当前的硬件设备、服务器容量、数据库工具和软件接口是否能支持系统要求。
    • 组织可行性 (Organizational)： 评估用户的使用意愿、培训需求和业务政策，以确保系统得到采纳。

真实企业案例：美国医保网站 (Healthcare.gov) 启动失败 (2013)

  • 最初的 Healthcare.gov 网站在启动时经历了严重的技术和组织规划疏忽。
  • 需求收集不善以及缺乏扩展性压力测试导致公开发布时服务器彻底崩溃。
  • 这凸显了在部署前进行严格的技术可行性评估的至关重要性。

参考链接： Healthcare.gov 的失败回顾

系统可行性研究三维度

可行性评估维度 核心思考问题 常用分析指标 关键风险点
经济可行性 (Economic) 我们是否应该做这项目？ 净现值 (NPV)、投资回报率 (ROI)、回本周期 低估了服务器维护及 API 接口调用运营成本
技术可行性 (Technical) 我们是否具备开发的技术能力？ 技术团队技能矩阵评估、硬件资源可用性 使用缺乏社区支持和成熟案例的实验性第三方库
组织可行性 (Organizational) 最终用户是否会积极使用该系统？ 用户满意度预期、业务工作流匹配度 习惯于依靠直觉决策的管理者的抵触和不信任
项目范围界定

精准界定项目开发边界，防止在后续开发过程中发生范围蔓延 (Scope Creep)。

Tips 提示

Be prepared to identify the three feasibility dimensions: Economic (money/ROI), Technical (hardware/software/servers), and Organizational (people/politics/adoption).
准备好识别三个可行性维度：经济可行性（资金/投资回报率）、技术可行性（硬件/软件/服务器）和组织可行性（人员/政策/采纳度）。
